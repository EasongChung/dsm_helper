## 1. Goal, scope and release boundary

Extend the **optional** Modern File Station browser delivered by Task 7A with genuinely working search, per-item/context and batch operations: selection dispatch, rename, deletion, favorites, ordinary sharing links, and legacy-supported copy/move. Creating a folder is included as the already-existing closely related file operation explicitly deferred by 7A. Reuse the already accepted browser, actual DSM models and legacy operations; do not replace backend request semantics.

**Not Task 7B:** uploading, downloading, file opening/image/video/text/PDF preview, transfer center, live background-task status/progress/cancel UI, external share intent destination, remote-mount management, virtual folders, archive/extract, share-link administration, File Request creation, new DSM transport/session SDK, or the default Files tab cutover. Task 7C owns transfer/preview/background-task wiring and final complete-feature cutover. Until 7C succeeds, **`打开现有功能` remains the normal complete legacy File Station**, and `试用新版文件浏览（测试）` remains explicitly opt-in.

## 3. Selected architecture and interaction semantics

1. **Reuse** `lib/new_ui/files/**` browser and existing `FileItem`, `Sharing`, `Api.copyMoveTask` / search helpers. Add narrow dependency-injectable operation/search adapters, typed results and a route-scoped action coordinator **without introducing a second DSM transport, SID cache or app-wide file-store**. Where the legacy raw helper cannot safely express search pagination, extend it backward-compatibly or wrap the existing `Api.dsm` entry surface after test of literal request fields; no wholesale rewrite.
2. Search is the preferred **single direct File Station App Bar action**, not an extra persistent toolbar. Existing sort/list-grid/refresh remain secondary controls and notifications keep their globally approved entry. Search is scoped to an **explicit verified current folder path**, not guessed `real_path`; root search is disabled until a real supported root scope is established. Search result page is a separate route/state so query/results do not corrupt directory pagination or selection. Empty/pending/failed/incomplete/finished results must be distinguishable.
3. In normal mode **long press** file/folder → context menu for *that one item*. Horizontal swipe → selection mode with exact path; selection-mode tap toggles; long press on a selected item → menu for the *selected set*. Selection App Bar keeps Back/exit/count/select-loaded; a contextual bottom operation bar offers only currently implemented valid actions (copy, move, delete, more). Do not expose nonworking download/preview actions until 7C. Grid and list parity is mandatory; no permanent checkbox gutter. Share-root rows remain navigation-first rather than editable root objects.
4. Menu action eligibility is driven by selection cardinality, directory/entry type, and any known DSM ACL evidence; **unknown ACL is not a guarantee of permission**, so attempts must preserve and surface server errors. Rename and create folder are single-item/current-directory actions; bulk delete/copy/move apply to a frozen selected-path snapshot. Selection must not auto-include later pages. Keep action targets tied to active context and exact paths, not row index, name or object instance.
5. **Mutation intent vs completion:** submit only after explicit user confirmation where destructive; disable repeat submits while pending; distinguish request failure, accepted request/task ID and server-observed completion. For immediate bool-returning calls (rename/create folder), refresh verified directory after success. For Delete and CopyMove, `taskid` means *queued/started only*; notify user, retain/refresh appropriately without claiming remote completion. Existing background-task event may be emitted as legacy compatibility, while Task 7C owns a modern task-status surface.
6. **No speculative result after context change:** bind operation to `contextId` and immutable source path(s); dispose/cancel UI continuation on account switch/navigate away and ignore late callbacks. Remote request already sent to A cannot be unsent; do not accidentally apply response or refresh to B. Reauth 119 follows existing global callback; timeout/permission/unknown DSM failure is not logout.
7. **Copy/move conflict risk:** legacy helper **unconditionally supplies overwrite=true**. Task 7B cannot silently present this as a safe non-overwriting operation. B5 has a **blocking confirmation gate**: before enabling remote CopyMove, explicitly freeze UX/policy from the real legacy request, verify on controlled DSM test files and obtain user approval for any overwrite risk. The plan's default safe behavior is **do not dispatch copy/move while this gate remains unresolved**. Do not change legacy backend request semantics, assume a preflight destination lookup is race-free, or invent a server-level atomic no-overwrite guarantee.
8. UI uses Material 3 approved density, single App Bar action/notification budget, existing error messaging conventions, accessible disabled/busy states, modal sheets/confirmations within system insets, light/dark theme and Android Back. No silent link disclosure: share URLs are shown/copied only after successful DSM response, not logged as diagnostics.

## 4. Preflight contract gaps and explicit stop conditions

| Gap | Determination | Required resolution / owner |
| --- | --- | --- |
| `T7B-GAP-01` copy/move overwrite | **Unresolved destructive policy:** legacy hard-codes overwrite true. | B5 *blocking gate*: user-approved warning/collision policy plus safe real-DSM fixture validation before enabling. Do not silently alter legacy payload. |
| `T7B-GAP-02` search completion/paging | Legacy Search list hard-codes 1000; unfinished result polling is not bounded in legacy, search form callback commented out. | B2: RED tests for >1000, repeat pages, task finished vs page complete, max bounded polling + path/context disposal; verify literal protocol on DSM when possible. If API fails to support next offset, report incomplete and require scope decision—not fabricated completeness. |
| `T7B-GAP-03` operation task completion | Delete and CopyMove return task IDs; Task 7C owns modern background task progress. | B4/B5: task-start acknowledgement only. Do not remove rows/claim completed by assumption. |
| `T7B-GAP-04` permissions and remote/virtual paths | Nullable ACL and special paths; no independent cross-DSM capability proof. | B1 capability/error classification. Test regular shares first; mark unsupported special/virtual/remote contexts as deferred or disable unsafe operations rather than guessing. |
| `T7B-GAP-05` share output / link policy | Ordinary `Sharing.create` returns links; full management/file requests beyond current scope. | B3: ordinary DSM-generated link only, no exposing incomplete link as success; no speculative expiration/password behavior. |
| `T7B-GAP-06` delete task launch vs completion | Existing model success may expose only `taskid` string, otherwise empty. | B4: explicit task-id validation, non-reentrant confirmation, distinguish accepted vs failed and preserve visible snapshot/selection when uncertain. |

**Nonblocking design decisions made here:** create folder belongs to file-operation Task 7B; ordinary sharing links are in scope, separate file-request/upload flow is not; search is a dedicated route and normal folder-scoped read; no default Files cutover or file-opening in this Task. Materially inconsistent observed server semantics are reported and gated, never quietly "fixed" in a widened legacy SDK refactor.

## 5. Acceptance principle

Each Batch follows TDD (real failing behavior RED, then GREEN), narrowly changed files, exact remote SHA/CI proof, an individual acceptance document and a stop gate. Physical DSM **mutations must be tested on dedicated expendable test folders/files**, never user data or root shares. Automated fake-server tests prove request handling and UI logic; they **do not** establish live DSM conflict semantics or completed tasks. B6 can close Task 7B only for verified operations, documenting skipped cases explicitly. Task 7C remains independently authorized and later supplies full File Station completeness.
